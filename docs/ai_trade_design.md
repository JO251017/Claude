# AI 거래 특화 재구성 설계안 (초안, 승인 전 - 코드 변경 없음)

## 1. 목표
2027년부터 늘어날 AI 에이전트 간 거래(에이전트가 후보를 평가·제안하고, 상대 에이전트/사람이 승인)에 맞춰, 현재 CLI 중심 구조를 **AI가 호출하는 인터페이스 + AI 거래용 판정 기준** 구조로 바꾼다.

## 2. 구조 (기존 코어는 유지, 어댑터만 추가)
```
[Claude: MCP 서버]  [GPT: 함수/액션 어댑터]  [CLI(현행)]
            \            |            /
         src/service  (공통 서비스 계층: 입력/출력 JSON 스키마, 멱등키, 감사 로그)
                         |
   src/sourcing(profit) · src/discovery(market, trends) · approval · SQLite   <- 현행 코어 그대로
```
- 코어(`profit.py` 등)는 수정하지 않는다. `src/service`가 코어를 호출하고, 어댑터는 서비스만 호출한다.
- 어댑터는 얇게 유지한다. MCP를 기준 구현으로 하고 GPT용은 같은 스키마에서 생성한다.
- 확인 필요: ChatGPT "플러그인"은 이전 형태가 종료되고 Actions/앱/MCP 지원으로 바뀐 것으로 알고 있다. 착수 전 최신 공식 문서로 현재 규격을 확인한다(규격 추측 금지).

## 3. MCP 도구 안(안)
| 도구 | 성격 | 설명 |
|---|---|---|
| `evaluate_candidate` | 읽기 | C·S·M(+F)을 받아 T_min, 순이익, 판정, 사유 반환 |
| `run_batch` | 쓰기(내부) | 키워드·시세·원가 입력으로 실행, run_id 반환 |
| `get_run_summary` | 읽기 | 결론·처리 수치·이상 징후 |
| `list_pending_approvals` | 읽기 | 승인 대기 후보 |
| ~~`record_approval`~~ | - | **제외(사용자 결정)**: 승인은 사람이 엑셀 → `approve import`로만 한다 |
- 모든 쓰기 도구는 멱등키 필수, 호출한 에이전트·모델·도구·입력 해시를 감사 로그에 남긴다.

## 4. 추가 판정 기준 (제안 - 정의 필요)
| 기준 | 목적 | 현행과의 관계 |
|---|---|---|
| 에이전트·거래 상대 식별/신뢰 등급 | 누구와 거래하는지 | 신규 |
| 데이터 신선도 TTL(기계 판독) | 오래된 시세로 자동 거래 방지 | 최신성 7·14일 규칙을 확장 |
| 반품·분쟁 정책의 기계 판독 가능 여부 | 수량당 배송비 같은 손해 조건 사전 차단 | ship_fee_rule 확장 |
| 재현 가능성(입력 해시·설정 해시로 판정 재현) | 에이전트 간 분쟁 시 근거 | 메타 시트의 설정 해시 확장 |
- 기존 가중치 점수 금지 원칙을 유지한다. 새 기준도 사전식(탈락 > 보류 > 통과)으로만 결합한다.

## 5. 충돌하는 기존 원칙 - 결정 필요
1. **DEC-008(네이버 데이터를 AI 요청에 넣지 않음)**: MCP로 결과를 AI에게 주면 성장률 등 파생값이 AI 컨텍스트에 들어간다. 후보: (a) 네이버 파생값은 MCP 응답에서 제외, (b) 파생값만 허용(원시 시계열은 계속 금지), (c) 약관 확인 후 허용. 약관 확인 전까지 (a)를 기본으로 한다.
2. **"승인 없는 외부 쓰기 금지"**: AI 자동 승인은 위임장 한도 내로만 허용할지, 전부 사람 승인으로 둘지.
3. **PRD 8장 제외 범위**: 에이전트 간 결제·주문 실행은 이번 범위에 넣지 않는다(후보 평가·승인 기록까지만).

## 8. 2c 결과 (사용자 위임: "알아서 만들어와")
### ChatGPT 연결 방식 - 별도 어댑터 대신 같은 MCP 서버
- OpenAI 공식 도움말·Apps SDK 문서(2026-10 확인)에 따르면 ChatGPT는 **원격 MCP 서버(공개 HTTPS + `/mcp`)**에 연결한다. 이전의 "플러그인" 방식 대신 이 방식을 쓴다.
  - 출처: https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt , https://developers.openai.com/apps-sdk/quickstart
  - 요금제별 허용 범위는 문서끼리 설명이 달라 **확인 필요**(개인 Pro는 읽기 도구만 가능하다는 설명 있음 - 이 서버는 읽기 도구뿐이라 해당 범위 안).
- 그래서 GPT용 코드를 따로 만들지 않고 `python -m src.mcp_server --transport http`(기본 `http://127.0.0.1:8000/mcp`, 이 컴퓨터에서만 접속)로 같은 서버를 띄운다.
- **외부 공개는 하지 않았다.** ChatGPT에 붙이려면 공개 HTTPS 주소가 필요한데, 인증 없이 열면 후보·원가 데이터가 누구에게나 보인다. 공개 전에 (1) ChatGPT의 Secure MCP Tunnel 또는 인증이 있는 터널, (2) 접속 인증 설정이 필요하다 - 사용자가 결정.

### 추가한 AI 거래용 기준(기계 판독 필드)
| 필드 | 의미 | 왜 필요한가 |
|---|---|---|
| `schema_version` | 응답 형식 버전 | 상대 에이전트가 형식 변화를 감지 |
| `input_hash` + `config_hash` | 같은 입력·설정이면 같은 결과 | 에이전트 간 분쟁 시 판정 재현. 숫자 형식(8000/"8000"/8000.0) 차이는 같은 해시 |
| `reason_codes` | 사유 코드(BELOW_TMIN, STALE 등) | 문구 대신 코드로 판단. 네이버 파생 사유는 `HIDDEN` |
| `stale` | 최신성 초과 여부 | 오래된 시세·원가로 자동 거래 방지 |
| `human_approved`, `run_decision` | 사람 승인 상태 | 승인은 사람만(사용자 결정). AI는 승인 여부만 읽음 |
| 도구 `list_approved_candidates` | 사람이 승인한 후보만 | **AI 거래 상대의 실행 대상은 이 목록뿐** |
- 판정 규칙(탈락 > 보류 > 통과)과 계산 코어는 바꾸지 않았다. 새 임계값도 만들지 않았다.

### 만들지 않은 것과 이유
- 거래 상대 신뢰 등급, 반품·분쟁 정책 판독: 판단에 쓸 실제 데이터(상대 에이전트 정보, 정책 원문)가 없어 기준을 지어내지 않았다. 데이터가 생기면 같은 방식(사유 코드 + 사전식 판정)으로 추가한다.
- 승인 쓰기 도구, 주문·결제: 사용자 결정으로 제외.
